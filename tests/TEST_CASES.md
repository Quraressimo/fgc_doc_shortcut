# 테스트 케이스

아래 케이스 중 DB 재생성·내보내기·폼 검증은 자동화되어 있습니다.
테스트는 `DB`와 `HTML`을 임시 폴더에 복사해 실행하므로 원본 파일을 변경하지 않습니다.

    py tests\test_copy_workspace.py

각 테스트의 설명과 실행·통과·실패 상태가 콘솔에 바로 출력됩니다.
폼 검증 케이스는 Node.js가 없으면 건너뛰며, 표의 나머지 화면 동작은 브라우저에서 수동 확인합니다.

| ID | 영역 | 테스트 절차 | 기대 결과 |
|---|---|---|---|
| DB-01 | DB 초기화 | 테스트 러너가 임시 복사본에서 `apply_sql.py`를 실행한다. | 테이블 생성과 데이터 입력이 성공하고, ID 중복이나 필수 태그 제약 위반이 없다. |
| DB-02 | DB 제약 | 임시 DB에 `tag1`을 빈 문자열 또는 공백만으로 INSERT 한다. | CHECK 제약으로 INSERT가 거부된다. |
| DB-03 | SQL 적용 실패 | 복사본의 `crud.sql` 끝에 존재하지 않는 테이블 INSERT를 추가하고 `apply_sql.py`를 실행한다. | 오류가 명시되고, 트랜잭션 롤백으로 기존 가이드 데이터가 보존된다. |
| DB-04 | DB 조회 | 임시 복사본에서 `only_db_read.py`를 실행한 전후 행 수를 비교한다. | 행과 스키마가 변경되지 않고, 조회된 행 수가 출력된다. |
| DATA-01 | 데이터 내보내기 | 테스트 러너가 임시 복사본에서 `export_guides.py`를 실행한다. | 생성된 데이터의 ID와 개수가 DB와 일치하고, 태그 그룹이 필터 설정과 일치한다. |
| DATA-02 | 잘못된 설정 JSON | 복사본의 `filter-groups.json`을 잘못된 JSON으로 바꾸고 내보내기를 실행한다. | 오류가 명시되고, 기존 `guides-data.js`가 덮어써지지 않는다. |
| UI-01 | 초기 화면 | `HTML\index.html`을 직접 연다. | 초기 안내 문구가 보이고, 검색이나 필터를 선택하기 전에는 가이드 카드가 표시되지 않는다. |
| UI-02 | 제목 검색 | 제목의 일부를 입력한 뒤 대소문자 차이가 있는 검색어와 일치하지 않는 검색어를 차례로 입력한다. | 제목에 포함되는 검색어는 해당 카드만 표시하고, 불일치 검색어는 빈 결과 안내를 표시한다. |
| UI-03 | 필터 조합 | 같은 태그 그룹에서 둘 이상 선택한 다음 다른 태그 그룹도 선택한다. | 같은 그룹의 선택은 OR, 서로 다른 그룹 간 선택은 AND로 적용된다. 선택 해제 후 결과도 갱신된다. |
| UI-04 | 필터 검색 | 필터 검색란에 캐릭터 이름 일부와 한글 초성(예: `대처법`의 `ㄷㅊㅂ`)을 입력한다. | 일치하는 필터 항목만 표시되고, 검색어를 지우면 필터 목록과 접힘 상태가 복원된다. |
| UI-05 | 추가 폼 캐릭터 검증 | 캐릭터 입력란에 필터 설정에 없는 임의의 이름을 입력하고 SQL 생성을 시도한다. 이어 설정에 등록된 캐릭터를 선택해 다시 시도한다. | 미등록 캐릭터는 오류 안내와 함께 제출이 막히고, 등록된 캐릭터는 제출할 수 있다. 공용 가이드는 캐릭터란을 비워 둘 수 있다. |
| FORM-01 | SQL 생성 | 공략 추가 창에서 정상 입력을 제출하고 생성 SQL을 임시 DB에 실행한다. | 올바른 INSERT 문이 생성되고 한 행이 저장된다. |
| FORM-02 | SQL 문자열 이스케이프 | 제목이나 캐릭터 이름에 작은따옴표를 포함해 SQL을 생성한 뒤 임시 DB에서 실행한다. | 값이 손상되거나 SQL 문법 오류가 나지 않고, 원래 문자열이 저장된다. |
| FORM-03 | 공백 입력 검증 | 제목, 캐릭터, 필수 태그 1, 선택 태그 각각에 공백만 입력하고 제출을 시도한다. 이후 허용 가능한 빈 선택값(공용 캐릭터 및 선택 태그)을 확인한다. | 공백만 입력한 필드는 제출이 막히고 오류 안내가 표시된다. 공용 캐릭터와 선택 태그는 완전히 비워 두면 허용되며, 제목과 태그 1은 비울 수 없다. |
| FORM-04 | 미등록 태그 검증 | 태그 입력란에 필터 설정에 없는 임의의 태그를 입력한 뒤 SQL 생성을 시도한다. 설정된 태그를 선택해 다시 시도한다. | 미등록 태그는 제출이 막히고 설정된 태그는 허용된다. |
| FORM-05 | 플랫폼 ID | ID 구간에 빈 번호가 있는 플랫폼과 가득 찬 구간을 각각 선택한다. | 빈 구간에서는 가장 작은 미사용 ID가 입력되고, 가득 찬 구간에서는 ID 입력이 비워지며 폼 검증 오류가 안내된다. |
| FORM-06 | SQL 복사 | 생성 SQL 복사를 눌러 클립보드 허용/차단 상황을 각각 확인한다. | 허용 시 복사 성공 메시지가 표시되고, 차단 시 SQL이 선택되며 직접 복사 안내가 표시된다. |
